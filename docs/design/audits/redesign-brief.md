## 3. 화면별 문제 (13건)

### 01 Connect (대조 컷 — 양호)
가장 완성도 높은 화면(화이트 CTA, 16pt 거터, 라벨-인풋 리듬 일정 — `evidence.md` 01 결함 없음). 잔여 문제 1건: **S-01** 상단 3줄 설명문이 텍스트 벽이고 HOST/PORT/TOKEN이 개발자 용어 그대로 노출, 하단 40% 공백. 초기 화면으로서 브랜드 모멘트 없음.

### 02 Runs list (홈)
- **S-02** 스폰 컴포저의 죽은 공간 — 리스타일로 150→126pt 후에도 빈 인풋+비활성 Submit이 화면 최대 시각 덩어리(`ctaDisabled` 16% 회색 알약). 첫 화면의 1차 액션이 비활성 덩어리로 시작한다.
- **S-03** CHATS 3행이 동일한 녹색 running 반복(C-4) — 무엇이 다른지 훑기 어렵다.
- **S-04** SESSIONS 아래 → 푸터 사이 대공백; 콘텐츠 앵커 없음.
- **S-05** 푸터 2 알약("Files & reports"/"Settings")이 목적지인지 액션인지 모호 — 아이콘·활성 상태 없음(§4 재판정).

### 03 Conversation
- **S-06** 이벤트마다 타임스탬프 반복(22:27/22:28/22:29) — 채팅 앱 관행은 분 단위 그루핑 1회 표기.
- **S-07** 어시스턴트 텍스트가 배경에 바로 놓여 사용자 버블과의 구분이 "버블 유무"뿐 — 화면이 채팅이 아니라 로그로 읽힌다.
- **S-08** 헤더: 제목 조기 절단("Refactor the SSE backpres…")+상태 칩+"Raw" 토글이 일반 텍스트 — 토글 어포던스 불명.
- **S-09** 전송 버튼이 어두운 회색 원 — 1차 액션의 시각 무게가 2차 수준.

### 04 Connecting 상태
**S-10** "Connecting to this task's session" 텍스트 1줄뿐 — 대기 상태의 진행 표현이 없어 멈춤으로 오인(정적 캡처 특성상 등록 모션 밖 표현은 신설 금지 — 문제로만 기록).

### 05/06 Attention (restyle 후)
- **S-11** raw run id("run_demo_attention…")가 디스플레이 타이틀 — 내부 식별자 노출+위계 붕괴(C-3). 카운트 라인("1 pending, 1 attention")은 화면에서 두 번째로 중요한 문맥인데 `inkMute` 소면적.
- **S-12** 질문 전문이 **옐로 텍스트 블록** — 색이 컨테이너 역할을 하고 있다(캐논 §2-1 "색은 마지막 수단" 위반). 글리프+핵심 단어만 warn, 본문은 ink여야 한다. 비활성 Submit 알약은 전 폭 회색 덩어리로 남아 C-2 반복.
- **S-13** 카드 하단 60%+ 대공백 후 좌하단 세로 스택 알약 2개 — `evidence.md`가 이미 "내비게이션 구조 변경 필요" 한계로 기록한 부분.

### 07 Released
가장 치명적: **타이틀+"1 done" 외에 아무것도 없는 80% 공백 화면.** 완료 요약·트랜스크립트·계속하기 제안이 없다. (S-11·S-13 동반)

## 4. 하단 pill 내비게이션 재판정

**판결: 위치는 옳다. 형태는 폐기하고 탭 바로 재탄생시킨다.**

| 판정 축 | 판정 | 근거 |
| --- | --- | --- |
| 엄지 도달 | **하단 유지 옳음** | 한손 엄지 아크는 하단 1/3에 집중 — iOS HIG 탭 바·Android bottom navigation·Notion/Codex/Linear 모바일이 모두 하단 내비. 상세 화면의 좌하단 **세로 스택** 알약(05–07)은 왼손잡이가 아니면 아크 바깥 |
| 관행 | **불합격** | 검증된 모바일 앱의 하단 내비는 아이콘+라벨+**활성 상태**를 가진 안정적 랜드마크다. Loop는 화면마다 구성이 다르다: 02는 균등 분할 텍스트 알약 2개, 05–07은 세로 스택 2개, 01/03은 아예 없음 — "여기가 내비다"라는 학습 가능한 위치가 없다 |
| 시각 무게 | **불합격** | 알약이 콘텐츠 버튼과 동일 어휘라 내비로 인식되지 않는다. 더 큰 문제로 **목적지**("Files & reports", "Settings")와 **액션**("Back to chats", "Back")이 같은 알약 어휘를 공유해 사용자가 목적지 모델을 세울 수 없다 |
| 캐논 정합 | **개정 필요** | `elevation.float`는 jump-pill 한정, 알약 어휘는 §3 반경의 pill 한 스텝 — "하단 내비"라는 구조 개념이 캐논 어디에도 등록돼 있지 않았던 것이 근본 원인. 탭 바 신설 시 §3에 내비 컴포넌트 조항과 아이콘 어휘(C-5) 등록이 수반되어야 한다 |

즉 "하단 pill 디자인 요소가 맞는가?"에 대한 답은 **"하단은 맞고, pill이 틀렸다"**다. 액션 성격의 알약("Back to chats")은 헤더 back 셰브론과 제스처로 흡수하고, 하단은 목적지 3개(Chats·Files·Settings) 전용으로 바꾼다.

## 5. 리디자인 방향 3건

### 5.0 추천 확정 (사용자 승인 대기)

**direction: A — "Quiet Accent" + 공통 교정 조합 (추천: 방향 A).**

| 판단 축 | 평가 | 근거 |
| --- | --- | --- |
| 참고 패턴 부합 | **최고** | Linear의 근흑 캔버스+잉크 4단+단일 액센트 예산, Notion/Codex 모바일의 아이콘+라벨 하단 탭 바 — 검증된 다크 생산성 앱 관행과 정확히 일치. C-1(표면 사다리)·C-2(액센트 부재)·C-5(아이콘 0개)·C-6(pill 남발)을 관행 패턴으로 직접 해소 |
| 구현 비용 | **최소** | 토큰 역할명 불변 — 값 교체 + `accent` 등 신설 2역할 추가면 이행. B는 토큰 전면 교체+터미널 미러 색온도 충돌로 비용 최대, C는 상단 세그먼트로 내비 구조 재설계 필요 |
| 위험 | **최저** | 캐논 §2·§4-3·§6-8 개정은 필요하나 DP lane 경유 절차가 이미 정의됨. 무색 미니멀 정체성 약화 가능성은 액센트를 활성/선택/포커스 전용으로 예산화해 통제. B의 재학습 비용(플로팅 독), C의 엄지 도달 불리·반관행 위험 없음 |

**기각 사유:** B — 터미널 미러(GitHub-dark 청록)와 웜 배경 색온도 충돌을 피하려면 팔레트 이중 교체가 필요해 비용 대비 이득 부족. C — 상단 세그먼트 컨트롤은 최상위 내비로서 엄지 도달·HIG 관행 양쪽에서 불리.

**조합 전제:** B의 메시지 그루핑(S-06), C의 attention 인박스·완료 요약(S-13)은 A 위에 조립 가능한 독립 컴포넌트 수정으로 공통 교정에 선반영한다.

> **사용자 승인 대기.** 승인(또는 B/C 선택) 시 그 선택이 구현의 기준이 된다. 승인 항목은 §6 참조.

### 방향 A — "Quiet Accent" (권장)

Linear식 근흑 + 단일 액센트 + 표준 탭 바. 현재 골격(무색 잉크 위계, 화이트 CTA, hairline 분리)을 유지하면서 빠진 층을 채운다.

- **색:** bg를 한 단계 깊게(`#0B0E13` 계열), 표면 3단 사다리 재조정(`#12161E/#181D27/#202734` — 단차 확대), hairline 0.12→0.16, `ink` 상향(`#F2F5F9`)·잉크 4단계화(Linear식). **단일 액센트 1개 신설**(인디고 계열, Linear 라벤더 패밀리) — 활성 탭·포커스 링·선택 상태·링크 전용. CTA는 화이트 반전 유지, 상태 삼합 유지.
- **컴포넌트:** 버튼 위계 3층 — 1차=화이트 필(radius.m 사각 계열), 2차=surface 필+헤어라인, 3차=텍스트. pill은 전송 원형과 상태 배지로 한정. 입력=채움+내부 헤어라인+포커스 시 액센트 링. 런 행=리딩 상태 열(도트)+타이틀+시간, 잦은 상태 단어는 mute(C-4). attention 패널=외곽선+좌측 warn 엣지, 질문 본문은 ink(S-12). 완료 화면에 요약 카드+다음 액션(S-13).
- **내비게이션:** **하단 탭 바 3탭**(Chats/Files/Settings — 아이콘+라벨, 활성=액센트), 상세 화면은 탭 바 숨기고 헤더 back+타이틀. 액션 알약 전부 제거.
- **트레이드오프:** (+) 모바일 관행 완전 부합, 상태·위계 가시성 최대, 기존 토큰 역할명 불변(값 교체+2역할 신설이면 이행 가능), 유료 호출 없이 시뮬레이터 검증 가능. (−) 무색 미니멀 정체성이 약화될 수 있고, 캐논 §2 폐쇄 집합·§4-3 "새 색상은 드리프트"·§6-8(제3 강조 금지)을 **개정**해야 한다(액센트=선택/활성 전용, CTA와 이원화 명문화). 아이콘 어휘 신규 등록(C-5) 필요.

### 방향 B — "Editorial Warm" (Notion식)

웜 그래파이트 다크 + 콘텐츠 퍼스트 타이포 + pill 아이덴티티 계승.

- **색:** 청회색→웜 중성으로 전면 교체(bg `#171717` 계열, 표면 `#1F1F23`+, 웜 잉크 `#E9E7E2`), 헤어라인 강화, 강조는 화이트 CTA 극소 + 포인트 1색.
- **컴포넌트:** 메시지 분 단위 그루핑(타임스탬프 1회 — S-06), 역할 라벨 소형 상시, 툴 카드를 리딩 글리프 열의 컴팩트 행으로, attention=외곽선 패널. 타이포 위계를 타입 크기로 해결(화면 타이틀 22–26 상시).
- **내비게이션:** 중앙 **플로팅 독**(아이콘 3개 pill — 현 pill 정체성 계승)+스와이프 백.
- **트레이드오프:** (+) 본문 가독성과 차분한 톤 최고, pill 아이덴티티 유지. (−) **터미널 미러와의 색온도 충돌** — `terminalLayout.ts`·syntax 5색이 GitHub-dark 청록 계열이라 웜 배경에서 코hesion이 깨진다(터미널 미러 팔레트까지 교체하면 비용 급증). 플로팅 독은 iOS 관행 이탈로 사용자 재학습 필요. 토큰 전면 교체로 §6-1 회귀 테스트 전부 재작성 — **비용 최대**.

### 방향 C — "Operator Console" (밀도)

오퍼레이터 도구 정체성을 전면화 — Linear 앱보다 인시던트 콘솔에 가깝게.

- **색:** 청회색 유지 + **attention 앰버를 브랜드 모멘트로 승격**(attention 화면의 최강조=앰버 CTA/엣지), 잉크 단계 강화, 표면 단차 확대.
- **컴포넌트:** 홈=스티키 섹션 헤더+행 밀도 상승, attention 인박스(대기 카드 큐+카운트 배지), 툴 출력을 터미널 미러 표면(mono+surfaceAlt)으로 통일, 컴포저 상시 도킹.
- **내비게이션:** **헤더 하단 세그먼트 컨트롤**(Chats|Files|Settings) — 하단 전체를 컴포저에 양보.
- **트레이드오프:** (+) 정보 밀도·전문 도구 정체성 최고, 엄지 영역을 입력에 온전히 양보. (−) 상단 세그먼트는 엄지 도달에 불리하고 HIG도 상단 세그먼트를 2차 수준으로 권고 — 최상위 내비로는 반관행. 시각 무게·인지 부하 상승으로 캐주얼 사용자에게 과밀. 앰버 승격은 §2-2 상태색 예산 조항 개정 필요.

### 권장과 조합

**A 채택 권장.** B의 메시지 그루핑(S-06)과 C의 attention 인박스·완료 요약(S-13)은 어휘 충돌 없이 A 위에 조립 가능한 독립 컴포넌트 수정이라, 방향 선택과 무관하게 공통 교정으로 선반영할 것을 제안한다.
