## 5. 관찰 사항 (차단 아님 — 승인 리뷰 참고)

1. **§1 승인 태스크 id 미배정.** ADR 필수 내용에 "승인 태스크 id"가 있으나 design.md는 "미배정 — accepted 전환 시 기재"로 필드+채움 규칙을 명시했다. `draft` 상태에서는 ADR의 accepted 조건과 모순되지 않으며, ADR의 "해당 없음 — 이유" 관행에 부합. 단, 승인 리뷰를 태스크가 아닌 리드 리뷰로 수행할 것이라 밝혔으므로 accepted 전환 시 이 필드의 채움 주체(승인자)가 명확해야 한다.
2. **EARS 문장의 계층명 언급.** R1/R3/R7 등이 "presentation 계층"을 요구사항 문장에 두었다. ADR은 "구현 방법(기술 스택·파일) 기술 금지"로 규정하는데, 이는 구현 방법이 아니라 **소유권·단일 원천의 위치 자체가 요구 사항**(감사 P2/P4-1의 원인 구조)이므로 의도적 선택으로 판단한다. 다만 형식 엄격 주의 관점에서는 계층명을 §5로 미룬 서술도 가능했으므로, 골격 재검토(ADR 부담·위험 (i)) 시 판례로 남겨둘 가치가 있다.
3. **부분 커버 2건의 성격.** P3-1 렌더링 반쪽과 P3-2는 "해소 안 함"이 아니라 "증거/결정 선행 조건부 연기"이고, 각각 T8 관찰 태스크와 D-5 후속 결정이 남아 있다. 커버리지 누락으로 분류하지 않는 근거다.
4. **§3 목표 6의 표현.** "1주차 이관은 출력 바이트 동일을 원칙으로"는 실행 정책에 가까운 서술이나 R6으로 정식 요구화돼 있어 실질 중복은 없다.

## 6. 검증 방법 및 한계

- 방법: ADR 9절 규격·감사 16항목·파운데이션 D/S/D-표기 3축과 design.md를 항목 단위 대조 + §7 표 독립 재계산 + 파일:줄 인용 6곳 스폰 체크(`grep`/`sed` 원 코드 대조).
- 한계: design.md의 태스크는 전부 승인 대기라 실제 실행·검증 명령 출력은 존재하지 않는다. 본 리뷰는 문서 정적 적합성 판정이며, 태스크 착수 후 `bun run check` 등 §9 명령 출력이 후속 증거다. 이 문서 자체는 읽기 전용 검증이라 `bun run check` 대상 코드 변경이 없다.
