- 일시정지, 재개, 지침 전달, 승인 응답과 취소를 저장된 실행에 적용한다. 열린 승인 요청을 재개로 우회할 수 없으며, 취소 요청과 실제 중단 완료를 구분한다.
- 실행 프로세스와 관찰 화면을 분리했다. 관찰 프로세스 종료 후에도 작업을 계속하며, 실행 프로세스 자체가 죽으면 중복 실행 없이 명시적 복구 절차를 안내한다.
- 실행 소유권과 상태 기록을 같은 저장 트랜잭션에서 검사한다. 이전 실행자의 늦은 결과·주의 요청이 새 실행을 변경하지 못한다.
- 독립 작업과 검증을 설정한 한도 안에서 병렬 실행한다. 의존 작업에는 이전 결과, 실패·검증 기록과 사용자 지침을 전달한다.
- 외부 자원 정리는 실제 종료를 확인하고 일시 오류를 재시도한다. 해결되지 않은 정리 실패는 실행을 완료 처리하지 않고 확인 요청으로 남긴다.
- Jev 실행 경로를 제거하고 공개 Rustra 버전을 고정했다. 인접한 Rustra 소스 없이 설치·생성·검사할 수 있다.

동일한 로컬 환경에서 한 번씩 측정한 진단 수치이며 성능 보증이나 실제 모델 비교가 아니다.

저장소 측정은 `cargo test -p loop-store --test projection_performance -- --ignored --nocapture`로 재현할 수 있다. 운영 데이터 크기, 공급자 지연 및 실행 환경에 따라 결과가 달라진다.

## 검증 범위와 사용상 구분

- 실제 인증을 사용하는 모델 호출, Herdr 화면에서의 종단 동작, 설치된 사용자 실행 파일 교체와 CI 서버 실행은 이번 검증에 포함하지 않았다.
- `steer`는 다음 배정·재시도에 반영된다. 이미 진행 중인 모델 호출의 입력을 소급해 바꾸지 않는다.
- 작업 범위 선언은 스케줄러의 충돌 방지 계약이다. 운영체제 수준의 파일 접근 격리는 아니다.
- 화면 종료와 실행 프로세스 장애는 다르다. 후자는 이전 작업·검증의 중단을 확인하고 `reconcile`한 뒤 재개한다.
- 기존에 병행 추가된 CLI `cleanup`은 저장된 실행 기록의 보존·삭제 명령이다. 외부 Git 작업 공간이나 Herdr 표면까지 자동으로 탐색해 지우는 기능으로 해석하지 않는다. 외부 자원을 명시한 orchestrator 정리 경로는 종료·안전 검사를 통과한 뒤 기록을 삭제한다.
- 기존 프로젝트 변경을 기준선으로 보존했다. 추가된 정리 CLI와 문서를 유지했으며, 기존의 '외부 정리 실패에도 기록 삭제' 테스트는 기록 보존 회귀 검사로 대체했다.
