# Herdr 0.8.2 탭 배치 조사, attempt 1

- kind: `research`
- date: 2026-09-21, Asia/Seoul
- Herdr: client/server `0.8.2`, protocol `20`, `compatible: yes`
- 의존성: 실행 중인 로컬 Herdr server와 설치된 `loop.agent` plugin
- 읽기 범위: Herdr CLI help와 plugin manifest
- 쓰기 범위: 격리 실험 workspace `w18`만 생성 후 종료, 이 보고서만 추가
- 금지 경계: credential 조회, model prompt, provider/authenticated CLI 호출 없음

## 결론

`herdr pane split`은 `--placement`를 제공하지 않는다. 따라서 split 결과를 tab으로
바꾸는 `pane split --placement tab` 조합은 지원되지 않는다. 같은 workspace에 새
tab을 만들려면 `herdr tab create`를 쓰고, plugin pane을 새 tab으로 열려면
`herdr plugin pane open --placement tab` 또는 manifest의 `[[panes]] placement =
"tab"`을 쓴다.

이 문서는 tab을 **생성하고 Herdr의 tab 목록에 별도 항목으로 존재시키는 것**을
검증했다. 여러 tab의 내용이 화면에 동시에 렌더링되는 UI 동작은 검증하지 않았고,
그렇게 주장하지 않는다. 한 tab 안에서 동시에 보이는 pane은 `pane split`의 범위다.

## 1차 문서 교차 확인

- Herdr의 [`v0.8.2 CLI reference`](https://github.com/herdrdev/herdr/blob/v0.8.2/docs/next/website/src/content/docs/cli-reference.mdx#L287-L340)는 workspace 생성이 첫 tab/root pane도 만든다고 정의하고, `tab create`, `pane split`, `pane move --new-tab`을 서로 다른 명령으로 열거한다.
- 같은 문서의 [`plugin pane open`](https://github.com/herdrdev/herdr/blob/v0.8.2/docs/next/website/src/content/docs/cli-reference.mdx#L519-L526)은 `tab`을 plugin pane placement로 열거한다.
- Herdr의 [`v0.8.2 plugin placement 문서`](https://github.com/herdrdev/herdr/blob/v0.8.2/docs/next/website/src/content/docs/plugins.mdx#L334-L349)는 manifest placement의 override 집합에 `tab`이 있고, split/tab/zoomed/overlay pane은 열린 뒤 일반 Herdr pane이라고 설명한다.

## 1. 명령 표면, help 근거

실행한 명령과 관찰 결과는 다음과 같다.

```text
$ herdr pane split --help
Options:
    --pane <ID>
    --current
    --direction <DIRECTION>  [possible values: right, down]
    --ratio <FLOAT>
    --cwd <PATH>
    --env <KEY=VALUE>
    --right-click <TARGET>   [possible values: herdr, pane]
    --focus
    --no-focus
```

`--placement`가 없다. 실제로 해당 옵션을 전달하면 다음의 CLI syntax error가
반환됐다.

```text
$ herdr pane split --pane w18:p1 --direction right --placement tab --no-focus
unknown option: --placement
```

반대로 plugin pane open help는 다음 placement 집합을 직접 열거한다.

```text
$ herdr plugin pane open --help
    --placement <PLACEMENT>
        [possible values: overlay, split, tab, zoomed]
    --workspace <ID>
    --target-pane <PANE>
    --direction <DIRECTION>  [possible values: right, down]
```

`herdr tab --help`는 `list`, `create`, `get`, `focus`, `rename`, `close`를,
`herdr workspace --help`는 `create`, `list`, `get`, `focus`, `rename`,
`report-metadata`, `close`를 제공한다. 이는 각각 tab과 workspace를 다루는 별도
primitive라는 help 수준의 근거다.

## 2. 실제 실행, workspace create, pane split, tab create

기존 workspace를 건드리지 않도록 `--no-focus`로 다음 격리 workspace를 만들었다.

```text
$ herdr workspace create --cwd /Users/loopy/dev/ll3/loop \
    --label loop-herdr-tab-placement-attempt-1 --no-focus
workspace_id: w18
root pane: w18:p1, tab_id: w18:t1
tab_count: 1, pane_count: 1
```

그 root pane을 실제 split했다.

```text
$ herdr pane split --pane w18:p1 --direction right \
    --cwd /Users/loopy/dev/ll3/loop --no-focus
new pane: w18:p2, tab_id: w18:t1
```

직후 `herdr tab list --workspace w18`은 `w18:t1` 하나와 `pane_count: 2`를
반환했다. `herdr pane layout --pane w18:p1`은 `w18:p1`, `w18:p2` 두 pane과
`direction: "right"` split 하나를 반환했다. 즉 **split은 원래 tab의 layout과
pane 수만 바꾸며 tab을 추가하지 않는다.**

그 다음 실제 tab을 만들었다.

```text
$ herdr tab create --workspace w18 --cwd /Users/loopy/dev/ll3/loop \
    --label research-tab --no-focus
tab_id: w18:t2, root pane: w18:p3, pane_count: 1
```

따라서 `tab create`는 같은 workspace 아래 새 root pane을 가진 별도 tab을 만드는
직접 검증된 명령이다.

## 3. `[[panes]] placement = "tab"` 실제 동작

설치된 local plugin의 source는 다음과 같이 tab 기본 배치를 선언한다.

```toml
# plugins/loop-agent/herdr-plugin.toml:14-18
[[panes]]
id = "agent"
title = "Loop Agent"
placement = "tab"
command = ["loop"]
```

`herdr plugin list --json`도 설치된 `loop.agent`의 `agent` pane을
`placement: "tab"`으로 보고했다. 모델 input 없이 이 pane을 두 방법으로 열었다.

```text
# manifest 기본값 사용, --placement 생략
$ herdr plugin pane open --plugin loop.agent --entrypoint agent \
    --workspace w18 --cwd /Users/loopy/dev/ll3/loop --no-focus
pane_id: w18:p4, tab_id: w18:t3, label: Loop Agent

# CLI에서 명시적 tab override
$ herdr plugin pane open --plugin loop.agent --entrypoint agent --placement tab \
    --workspace w18 --cwd /Users/loopy/dev/ll3/loop --no-focus
pane_id: w18:p5, tab_id: w18:t4, label: Loop Agent
```

`herdr tab list --workspace w18`의 최종 상태는 `w18:t1`(2 panes),
`w18:t2`(1 pane), `w18:t3`(1 pane), `w18:t4`(1 pane)이었다. 각각
`w18:p4`, `w18:p5`에 대해 `pane layout`을 읽으면 `splits: []`와 전체 영역을
차지하는 하나의 pane이 나왔다. 그러므로 manifest 기본값과 CLI의 명시적
`--placement tab`은 모두 기존 tab을 split하지 않고 **새 tab의 root pane**을
만든다는 것이 직접 실행으로 확인됐다.

### 추측과 미검증 경계

- **관찰:** 같은 `loop.agent/agent` entrypoint를 두 번 열면 `w18:t3`, `w18:t4`가
  생긴다.
- **추측:** 서로 다른 여러 `[[panes]]` entrypoint도 각각 `placement = "tab"`으로
  열면 별도 tab이 될 가능성이 높다.
- **미검증:** 이 plugin에는 entrypoint가 하나뿐이므로, 서로 다른 entrypoint 조합은
  plugin을 새로 만들거나 수정하지 않는 한 이번 범위에서 실행하지 않았다.
- **미검증:** `overlay`, `split`, `zoomed`의 실제 geometry와 tab UI의 동시 표시
  규칙은 검사하지 않았다. help가 지원 값으로 열거한다는 사실만 확인했다.

## 4. workspace close 실제 동작

종료 직전 `herdr workspace get w18`은 `tab_count: 4`, `pane_count: 5`를
반환했다. 생성한 workspace만 다음 명령으로 닫았다.

```text
$ herdr workspace close w18
{"type":"ok"}
```

그 후 `herdr workspace list`에 `w18`은 없었다. 따라서 create부터 tab/pane/plugin
배치, close까지의 격리 실험 lifecycle은 실제로 완료됐고, 기존 workspace와 pane은
close하지 않았다.

## 5. 같은 workspace에서 여러 tab을 만드는 후보

### 후보 A, native tab과 tab 내부 split

```text
workspace W
├─ tab 1: control, 필요하면 pane split으로 상태/명령을 나란히 둠
├─ tab 2: research shell, tab create
└─ tab 3: verification shell, tab create
```

```bash
herdr tab create --workspace "$W" --cwd "$PWD" --label research --no-focus
herdr tab create --workspace "$W" --cwd "$PWD" --label verify --no-focus
herdr pane split --pane "$CONTROL_ROOT" --direction right --no-focus
```

`tab create`와 `pane split`의 서로 다른 결과는 위에서 직접 검증했다. raw shell
tab을 원하는 경우 가장 단순한 조합이다.

### 후보 B, plugin pane을 tab으로 반복 open

```text
workspace W
├─ tab 1: 기존 control pane
├─ tab 2: Loop Agent instance 1, placement tab
└─ tab 3: Loop Agent instance 2, placement tab
```

```bash
herdr plugin pane open --plugin loop.agent --entrypoint agent \
  --workspace "$W" --placement tab --cwd "$PWD" --no-focus
```

이 명령을 두 번 실행해 별도 `w18:t3`, `w18:t4`를 만든 것이 직접 근거다. manifest에
`placement = "tab"`이 있으면 `--placement tab`은 생략 가능했고, 같은 결과를
확인했다.

### 후보 C, control tab과 plugin worker tab 혼합

```text
workspace W
├─ tab 1: control, 필요 시 split
├─ tab 2: plugin worker, placement tab
└─ tab 3: 별도 raw research/verify tab, tab create
```

이는 후보 A와 B의 직접 검증된 primitives만 조합한 설계안이다. `w18:t1`의 split
layout과 `w18:t3`/`w18:t4`의 single-pane layout이 같은 workspace 안에 함께
존재한 것이 이 조합의 실행 근거다.

### 후보 D, 기존 pane을 새 tab으로 이동

```bash
herdr pane move "$PANE" --new-tab --workspace "$W" --no-focus
```

이는 v0.8.2 공식 CLI reference에 명시된 조합이다. 이번 attempt에서는 새 pane을
만들어야 하는 A/B/C만 실제 실행했으므로, 이 후보의 move 이후 geometry와 process
context는 **문서 근거만 있고 실행 미검증**이다.
