# Gajae-Code와 Loop: 개발 속도·steering·TUI 비교

- 조사일: 2026-09-27
- Gajae-Code 원본: <https://github.com/Yeachan-Heo/gajae-code>, `main`의 `ec17cb15a3dae2d201752fb91297b0e181faf427`을 고정해 문서·소스·테스트 정의를 읽었다.
- Loop: 이 작업 트리의 소스와 [Pi Lead TUI 실행 기록](../findings/pi-lead-tui-development-flow-verification.md)을 읽었다. 작업 트리에는 병행 작업의 미커밋 변경이 많다. 아래 비교는 릴리스 보증이 아니다.
- 범위: 두 제품의 동일 과제 벤치마크, Gajae-Code 설치·실행, 실제 공급자 호출은 수행하지 않았다. **기능이 구현된 코드가 있다는 사실과 실제 개발 속도 향상은 별개**다.

## 먼저 구분할 것

Gajae-Code(`gjc`)는 Pi 확장이 아닌 **자체 TUI·SDK를 가진 독립 코딩 에이전트**다. 자체 agent session, 도구, subagent, workflow skill을 묶는다. README는 실험적 beta라고 명시한다. `gjc --tmux`는 tmux 기반 *leader session* 시작이고, 확인한 TUI의 `TasksPaneComponent`는 여러 종류의 작업을 모아 보여 주는 읽기 전용 목록이다. 이것만으로 Loop가 원하는 **Herdr 안의 Pi Lead 대화 + 실행 중 worker 탭**과 동일한 UX라고 볼 수 없다. [README](https://github.com/Yeachan-Heo/gajae-code/blob/ec17cb15a3dae2d201752fb91297b0e181faf427/README.md#L42-L100), [tasks pane source](https://github.com/Yeachan-Heo/gajae-code/blob/ec17cb15a3dae2d201752fb91297b0e181faf427/packages/coding-agent/src/modes/components/tasks-pane.ts#L1-L52).

Gajae-Code에는 `ManagedTaskGraph`와 자원 겹침 검사도 있다. 다만 해당 문서는 이를 **opt-in enrolled caller의 private durable domain**, 초기에 Broker WebSocket으로 접근하는 **test-only** `task.dag` 경계라고 설명하고, 일반 spawn·editor·raw shell은 보호 밖이라고 명시한다. Gajae-Code의 모든 subagent 실행이 이 DAG를 거친다고 가정하면 안 된다. Loop의 Rust graph-first DAG와 단순히 동등하다고 적을 근거도 없다. [managed task DAG boundary](https://github.com/Yeachan-Heo/gajae-code/blob/ec17cb15a3dae2d201752fb91297b0e181faf427/docs/managed-task-dag.md#L1-L14), [M2 wire](https://github.com/Yeachan-Heo/gajae-code/blob/ec17cb15a3dae2d201752fb91297b0e181faf427/docs/managed-task-dag.md#L77-L90).

## Loop에 대한 우선 제안

1. **P0: steer 반영 증명.** 자연어 변경 요청마다 이전 허용 기준, 변경된 허용 기준, 대상 task, worker 접수 상태, 독립 검사 결과를 한 receipt에 연결한다. 현재 `guidance_delivered`만으로 완료를 말할 수 없다. [Loop 실측](../findings/pi-lead-tui-development-flow-verification.md).
2. **P0: 작은 작업의 총 시간 측정과 fast path.** 동일 파일·동일 모델·동일 검사에서 Pi Lead→graph→Herdr worker 시작과 검증 완료 시간을 반복 측정한다. Gajae-Code의 직접 leader 편집이나 재개가 유리한지는 Loop의 안전 계약을 유지하는 조건에서만 채택한다. [Gajae-Code delegation guidance](https://github.com/Yeachan-Heo/gajae-code/blob/ec17cb15a3dae2d201752fb91297b0e181faf427/packages/coding-agent/src/defaults/gjc/skills/ultragoal/SKILL.md#L199-L228).
3. **P1: 문맥 예산 도구.** 구조 요약, 원문 재조회, 큰 출력의 검색 가능한 artifact, 결과의 짧은 Pi 위젯/상세 조회를 묶어 비교한다. 토큰 감소와 정답률을 같이 측정한다. [Gajae-Code read](https://github.com/Yeachan-Heo/gajae-code/blob/ec17cb15a3dae2d201752fb91297b0e181faf427/packages/coding-agent/src/tools/read.ts#L2957-L3004), [artifact](https://github.com/Yeachan-Heo/gajae-code/blob/ec17cb15a3dae2d201752fb91297b0e181faf427/docs/blob-artifact-architecture.md#L125-L180).
4. **P1: 경계 기반 검토.** 중간 node에는 집중 검사, 통합 지점에는 누적 diff와 변경 허용 기준을 다루는 한 번의 독립 검토를 적용한다. 위험이 큰 변경에서만 병렬 검토 lane을 쓴다. [Gajae-Code boundary](https://github.com/Yeachan-Heo/gajae-code/blob/ec17cb15a3dae2d201752fb91297b0e181faf427/packages/coding-agent/src/defaults/gjc/skills/ultragoal/SKILL.md#L244-L304).
5. **P2: worker 재개·비용 영수증.** 완료 탭을 닫는 현재 선택은 유지하고, 같은 영역 후속 작업에서 보존된 요약/세션을 재활용할 수 있는지 측정한다. 각 worker의 추가 비용과 실제 결과를 비교한다. [Gajae-Code reuse](https://github.com/Yeachan-Heo/gajae-code/blob/ec17cb15a3dae2d201752fb91297b0e181faf427/packages/coding-agent/src/defaults/gjc/skills/ultragoal/SKILL.md#L216-L228), [receipt](https://github.com/Yeachan-Heo/gajae-code/blob/ec17cb15a3dae2d201752fb91297b0e181faf427/packages/coding-agent/src/task/receipt.ts#L1-L64).

## 그대로 옮기지 않을 것

- **`deep-interview → ralplan → ultragoal`을 모든 요청에 의무화:** 문서 자체가 작은 단일 영역 수정의 `ralplan` 생략을 허용한다. [skill](https://github.com/Yeachan-Heo/gajae-code/blob/ec17cb15a3dae2d201752fb91297b0e181faf427/packages/coding-agent/src/defaults/gjc/skills/ultragoal/SKILL.md#L225-L228).
- **Gajae-Code의 독립 TUI/SDK를 Pi·Herdr 대신 채택:** 사용자가 선택한 단일 Pi Lead·Herdr worker 흐름과 다르고, 이 조사에는 동일 작업의 우수한 개발 속도 증거가 없다. [README](https://github.com/Yeachan-Heo/gajae-code/blob/ec17cb15a3dae2d201752fb91297b0e181faf427/README.md#L42-L100), [Loop 실측](../findings/pi-lead-tui-development-flow-verification.md).
- **접수된 steer를 적용된 변경으로 표기:** Gajae-Code도 `queued`와 결과 불확실성을 분리한다. [subagent](https://github.com/Yeachan-Heo/gajae-code/blob/ec17cb15a3dae2d201752fb91297b0e181faf427/packages/coding-agent/src/tools/subagent.ts#L381-L437), [Q30](https://github.com/Yeachan-Heo/gajae-code/blob/ec17cb15a3dae2d201752fb91297b0e181faf427/docs/sdk.md#L471-L482).
