## Executive finding

Loop creates four artifact families per run:
1. **Herdr surfaces** (workspace, per-worker tab/pane, agent registration)
2. **Worktree / working directory files** (`workingDirectory` inputs, task write-scope outputs, CLI temp dirs)
3. **SQLite state** in `crates/loop-store` (`loop.sqlite` + WAL/SHM sidecars, 9 relation tables)
4. **Provider process and session state** in `packages/providers` (detached process groups, CLI session caches, in-memory Maps)

Only two of these have any production removal path today, and both are strictly partial:
1. [`HerdrWorkerRuntime.start`](file:///Users/loopy/dev/ll3/loop/packages/herdr/src/client.ts#L77) closes the worker pane only when the launch itself throws during startup rollback (`client.ts:104-106`).
2. [`Orchestrator.#cancel`](file:///Users/loopy/dev/ll3/loop/packages/orchestrator/src/coordinator.ts#L213-L223) cancels live workers via their providers and appends `RunCancelled` to SQLite, but closes neither panes, nor tabs, nor workspaces, nor database rows.

Removal primitives that exist in code but have **no production caller**:
- [`HerdrWorkerRuntime.cleanup`](file:///Users/loopy/dev/ll3/loop/packages/herdr/src/client.ts#L172) (`pane close` + turn-map clear, idempotent-tolerant of already-gone panes since pass 6) — called only from [`packages/herdr/test/lifecycle.test.ts:69`](file:///Users/loopy/dev/ll3/loop/packages/herdr/test/lifecycle.test.ts#L69).
- [`AgyStreamDriver.dispose`](file:///Users/loopy/dev/ll3/loop/packages/providers/src/antigravity/driver.ts#L264) — called only from [`packages/providers/test/antigravity-persistent.test.ts:96,117,132`](file:///Users/loopy/dev/ll3/loop/packages/providers/test/antigravity-persistent.test.ts#L96).
- [`AgyPersistentProvider.disposeAll`](file:///Users/loopy/dev/ll3/loop/packages/providers/src/antigravity/persistent.ts#L175) — **zero callers anywhere**.

Nothing in the repository executes `DELETE FROM` (verified by grep across `crates/`); the `ON DELETE CASCADE` foreign keys in [`crates/loop-store/src/schema.rs`](file:///Users/loopy/dev/ll3/loop/crates/loop-store/src/schema.rs) remain completely dormant.

The clutter audit ([`docs/research/2026-09-21-herdr-pane-clutter-audit-attempt-1.md`](file:///Users/loopy/dev/ll3/loop/docs/research/2026-09-21-herdr-pane-clutter-audit-attempt-1.md)) confirmed this accumulation in a live environment: workspaces `w15` and `w16` from previous runs remained open with idle Codex workers and lingering root shells.

Ownership follows [`docs/architecture.md`](file:///Users/loopy/dev/ll3/loop/docs/architecture.md): Herdr owns workspaces/tabs/panes/processes, Loop owns SQLite durable state, each provider owns its external session store. Loop's primary architectural gaps are:
1. Missing teardown hooks at run completion.
2. Non-persistence of external identifiers (e.g. `workspaceId`, `session_id`) needed for post-hoc or crashed-run cleanup.
3. Lack of a deterministic Rust-side deletion command in `crates/loop-store` / `crates/loop-bridge`.

## Removal-path gaps (ranked by severity)

1. **Herdr worker tabs and panes survive indefinitely (A2, A3, D7)**:
   - *Impact*: Clutter accumulation in Herdr workspace (documented in pane clutter audit).
   - *Root cause*: [`HerdrAgentProvider.#wait`](file:///Users/loopy/dev/ll3/loop/packages/providers/src/herdr-agent.ts#L133) reads terminal output and transitions state, but never calls [`HerdrWorkerRuntime.cleanup`](file:///Users/loopy/dev/ll3/loop/packages/herdr/src/client.ts#L172).
   - *Remediation*: Add a teardown step in `HerdrAgentProvider` (or in `Orchestrator.run` / `#cancel`) calling `runtime.cleanup(handle)`.

2. **Detached Antigravity process groups are orphaned on crash/kill (D2)**:
   - *Impact*: Lingering background `agy` processes consuming CPU/RAM after Loop exits.
   - *Root cause*: `AgyStreamDriver` spawns with `detached: true` (`driver.ts:100`). [`AgyStreamDriver.dispose`](file:///Users/loopy/dev/ll3/loop/packages/providers/src/antigravity/driver.ts#L264) is test-only, [`AgyPersistentProvider.disposeAll`](file:///Users/loopy/dev/ll3/loop/packages/providers/src/antigravity/persistent.ts#L175) has zero callers, and no signal handlers exist in `main.ts` or `coordinator.ts`.
   - *Remediation*: Register `process.on("SIGTERM")` / `SIGINT` / `exit` handlers in orchestrator CLI to execute `disposeAll()`.

3. **Herdr workspace is never closed and its ID is never persisted (A1)**:
   - *Impact*: In-memory `workspaceId` is lost when orchestrator exits; workspace remains open indefinitely.
   - *Root cause*: No workspace close call exists in Loop (the CLI verb `herdr workspace close` is available and verified); `workspaceId` is not stored in SQLite.
   - *Remediation*: Persist `workspace_id` alongside `run_id` or implement an end-of-run workspace cleanup command (`herdr workspace close <workspaceId>`).

4. **No Rust-side deletion policy for SQLite store rows (C2)**:
   - *Impact*: Database rows accumulate forever; no command exists to prune old runs.
   - *Root cause*: No `DELETE FROM` statements exist in `crates/loop-store` or `crates/loop-bridge`.
   - *Remediation*: Per [`AGENTS.md`](file:///Users/loopy/dev/ll3/loop/AGENTS.md) boundary rules, implement `delete_run` / `purge_runs` in `crates/loop-store` and `crates/loop-bridge`, run `bun run codegen`, and expose through typed protocol.

5. **`workers.session_id` and `provider` columns are not populated (C3)**:
   - *Impact*: Inability to audit or clean up external provider sessions from database records alone.
   - *Root cause*: `apply_indexes` does not write `session_id` or `provider` in the `WorkerStarted` insert (`sqlite.rs:185`); upstream, `sessionId` is already available on `WorkerResult` (`packages/providers/src/types.ts:45`) but is dropped at the orchestrator/bridge boundary (see C3).
   - *Remediation*: Pass `provider` and `sessionId` through the `WorkerStarted`/`WorkerFinished` events or update on completion; extend `WorkerResultInput` and run `bun run codegen`.

6. **Acceptance test temp directory leak (B3)**:
   - *Impact*: `/tmp/loop-acceptance-*` directories accumulate on developer machines.
   - *Root cause*: `verifyInstall` in [`packages/cli/src/main.ts`](file:///Users/loopy/dev/ll3/loop/packages/cli/src/main.ts#L486) creates the directory at `main.ts:518` with no cleanup.
   - *Remediation*: Add `rmSync(acceptanceDir, { recursive: true, force: true })` in a `finally` block.
