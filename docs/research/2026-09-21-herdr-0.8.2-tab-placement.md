# Herdr 0.8.2 탭 배치 조사

- kind: `research`
- attempt: `0`
- date: `2026-09-21` (Asia/Seoul)
- workspace: `/Users/loopy/dev/ll3/loop`
- Herdr: `0.8.2`, protocol `20`
- result: **`pane split` 자체는 tab 배치를 지원하지 않음; `plugin pane open`과 `[[panes]] placement = "tab"`은 새 tab을 만듦**

## 범위와 안전 경계

이번 조사는 실제 Herdr 관리 pane 안에서 수행했다. `HERDR_ENV=1`과 현재
pane `w16:p3`를 확인한 뒤, 기존 workspace를 닫지 않도록 별도 실험
workspace `w17`만 만들고 사용했다. 실험 workspace에는 model prompt를 보내지
않았으며 유료 모델 호출과 credential 조회를 하지 않았다. plugin pane이
실행한 `loop`의 초기 화면은 idle 상태였고, Herdr가 표시한 사용량은
`0.0%`였다.

실험에서 만든 `w17`은 마지막에 `herdr workspace close w17`로 닫았고, 종료 후
`herdr workspace list`에 `w17`이 남지 않는 것을 확인했다. 기존 workspace와
pane은 닫지 않았다.

## 1. 버전과 명령 표면

### 관찰: 버전

```text
$ herdr --version
herdr 0.8.2
```

`herdr status`는 client/server 모두 `0.8.2`, protocol `20`, `compatible: yes`를
반환했다.

### 관찰: `pane split` help

```text
Usage: herdr pane split [OPTIONS] [PANE_ID]

Options:
      --pane <ID>
      --current
      --direction <DIRECTION>  [possible values: right, down]
      --ratio <FLOAT>
      --cwd <PATH>
      --env <KEY=VALUE>
      --right-click <TARGET>   [possible values: herdr, pane]
      --focus
      --no-focus
```

여기에는 `--placement`가 없다. 실제로 다음 명령도 layout을 변경하지 않고
exit code `2`와 함께 실패했다.

```text
$ herdr pane split --pane w17:p1 --direction right --placement tab --no-focus
unknown option: --placement
```

### 관찰: `plugin pane open` help

```text
Usage: herdr plugin pane open [OPTIONS]

Options:
      --plugin <ID>
      --entrypoint <ID>
      --placement <PLACEMENT>
          [possible values: overlay, split, tab, zoomed]
      --workspace <ID>
      --target-pane <PANE>
      --direction <DIRECTION>  [possible values: right, down]
      --cwd <PATH>
      --env <KEY=VALUE>
      --focus
      --no-focus
```

따라서 `tab`은 일반 pane split의 옵션이 아니라 plugin pane 배치 옵션이다.
이것은 help 텍스트로 직접 확인한 사실이다.

### 관찰: tab과 workspace 명령

`herdr tab --help`에는 `list`, `create`, `get`, `focus`, `rename`, `close`가
있다. `tab create --help`는 `--workspace`, `--cwd`, `--label`, `--focus`,
`--no-focus`를 제공한다. `workspace --help`에는 `create`, `list`, `get`,
`focus`, `rename`, `report-metadata`, `close`가 있다.

즉, raw terminal을 여러 tab으로 구성할 때는 `tab create`를 사용하고,
pane을 같은 tab 안에 나누려면 `pane split`을 사용한다.

## 2. 실제 실행: workspace create/close와 pane split

### Workspace 생성

실험 명령:

  --cwd /Users/loopy/dev/ll3/loop \

  "root_pane": {"pane_id": "w17:p1", "tab_id": "w17:t1"}

```bash

실행 결과는 새 pane `w17:p2`였고 tab은 계속 `w17:t1`이었다.

  "tabs": [

```

동일 tab의 layout도 `splits`에 `direction: "right"` 하나와
`w17:p1`, `w17:p2` 두 pane을 반환했다. 즉 `pane split`은 **pane 수와
분할 layout만 변경**하며 tab을 추가하지 않는다.

## 3. `[[panes]] placement = "tab"` 실제 동작

### 소스 근거

Loop plugin manifest는 다음과 같다.

```toml
[[panes]]
id = "agent"
title = "Loop Agent"
placement = "tab"
command = ["loop"]
```

근거: [`plugins/loop-agent/herdr-plugin.toml:14-18`](../../plugins/loop-agent/herdr-plugin.toml:14).

`herdr plugin list --json`도 설치된 `loop.agent` plugin의 pane을
`{"id":"agent","placement":"tab"}`로 반환했다.

### 관찰: manifest 기본값을 따른 open

placement 인자를 생략하고 manifest의 기본값을 사용했다.

```bash
herdr plugin pane open \
  --plugin loop.agent \
  --entrypoint agent \
  --workspace w17 \
  --cwd /Users/loopy/dev/ll3/loop \
  --no-focus
```

결과:

```json
{
  "plugin_pane": {
    "plugin_id":"loop.agent",
    "entrypoint":"agent",
    "pane": {
      "pane_id":"w17:p4",
      "tab_id":"w17:t3",
      "label":"Loop Agent"
    }
  }
}
```

그 직후 tab 목록은 `w17:t1`(pane 2), `w17:t2`(pane 1),
`w17:t3`(pane 1)이었다. `w17:t3`의 layout은 `splits: []`이고 pane 하나가
전체 영역을 차지했다. 따라서 `placement = "tab"`은 plugin pane을 기존
tab의 split으로 넣지 않고 **새 tab의 root pane으로 연다**.

### 관찰: CLI에서 `--placement tab`을 명시한 open

같은 plugin entrypoint를 이번에는 placement로 명시했다.

```bash
herdr plugin pane open \
  --plugin loop.agent \
  --entrypoint agent \
  --placement tab \
  --workspace w17 \
  --cwd /Users/loopy/dev/ll3/loop \
  --no-focus
```

결과는 다시 새 tab이었다.

```json
{
  "plugin_pane": {
    "pane": {
      "pane_id":"w17:p5",
      "tab_id":"w17:t4",
      "label":"Loop Agent"
    }
  }
}
```

`w17:t4` 역시 `pane_count: 1`, `splits: []`였다. 즉 manifest 기본값과
CLI override 양쪽에서 tab 배치가 재현됐다.

### 추측/미검증 경계

- **관찰:** 동일 `loop.agent/agent` entrypoint를 두 번 열었더니 `w17:t3`,
  `w17:t4`라는 독립 tab 두 개가 생겼다.
- **추측:** 하나의 manifest에 서로 다른 `[[panes]]` entrypoint를 여러 개
  선언하고 각각 `placement = "tab"`으로 열면 같은 workspace에 각각의 tab이
  생길 것으로 보인다. Herdr help와 현재 manifest 구조는 이를 허용하는
  표면을 보여주지만, 이번 실행에서는 서로 다른 pane entrypoint가 있는
  plugin을 만들거나 설치하지 않았으므로 그 조합 자체는 직접 검증하지
  않았다.
- **미검증:** `overlay`, `split`, `zoomed`의 실제 geometry와 기존 target
  tab 선택 규칙은 이번 조사 범위가 아니다. help에서 허용 값인 것만
  확인했다.

## 4. Workspace close 실제 동작

닫기 직전 `herdr workspace get w17`은 다음을 반환했다.

```json
{
  "workspace": {
    "workspace_id":"w17",
    "tab_count":4,
    "pane_count":5,
    "label":"loop-herdr-research-082"
  }
}
```

```bash
herdr workspace close w17
```

결과는 `{"type":"ok"}`였고, 이후 `herdr workspace list`에는 `w17`이
없었다. 따라서 workspace close는 실험 workspace와 그 안의 4 tab/5 pane을
정리하는 데 성공했다. 이 실험은 사용자가 명시한 생성/종료 흐름의 실제
실행 증거다.

## 5. 같은 workspace에서 여러 tab으로 보이게 하는 조합 후보

### 후보 A — native tab + tab별 raw pane

```text
workspace W
├─ tab 1: lead 또는 shell
│  ├─ pane 1
│  └─ pane 2  (pane split으로 같은 tab에 배치)
├─ tab 2: research shell       (tab create)
└─ tab 3: verification shell   (tab create)
```

실제 확인된 명령 조합은 다음이다.

```bash
herdr workspace create --cwd "$PWD" --label loop --no-focus
herdr tab create --workspace "$W" --label research --cwd "$PWD" --no-focus
herdr tab create --workspace "$W" --label verify --cwd "$PWD" --no-focus
herdr pane split --pane "$ROOT_PANE" --direction right --no-focus
```

근거 수준은 **직접 검증**이다. `tab create`는 새 tab/root pane을 만들고,
`pane split`은 선택한 tab 안의 pane만 늘린다.

### 후보 B — plugin entrypoint를 tab으로 반복 배치

```text
workspace W
├─ tab 1: 기존 작업
├─ tab 2: plugin entrypoint A (placement = "tab")
└─ tab 3: plugin entrypoint B 또는 A의 두 번째 인스턴스
```

현재 Loop plugin에서는 `agent` entrypoint 하나를 두 번 열어도 이 조합이
실제로 `w17:t3`와 `w17:t4`로 만들어졌다. 서로 다른 A/B entrypoint를 여러
개 선언하는 부분은 위의 추측 경계에 해당한다.

```bash
herdr plugin pane open --plugin loop.agent --entrypoint agent \
  --workspace "$W" --placement tab --cwd "$PWD" --no-focus
```

manifest에 이미 `placement = "tab"`이 있으면 `--placement tab` 생략도
동일하게 동작했다.

### 후보 C — control tab과 worker tab 혼합

```text
workspace W
├─ tab 1: control/lead (필요하면 pane split으로 상태 pane 추가)
├─ tab 2: research plugin (placement = "tab")
└─ tab 3: verification plugin 또는 raw shell
```

이 후보는 A와 B의 실제 확인된 primitive를 조합한 설계안이다. **추론:**
Herdr는 tab을 workspace 아래 독립 단위로 관리하므로, control tab의 split과
plugin tab의 단일 root pane은 서로 다른 layout 상태를 유지할 것이다. 이번
실행에서도 `w17:t1`의 split layout과 `w17:t3`/`w17:t4`의 단일-pane layout이
동시에 존재했다.

## 결론

1. `herdr pane split`에는 `--placement`가 없고, 실행으로도 거부됨을
   확인했다. 따라서 `pane split --placement tab`은 지원 조합이 아니다.
2. 같은 workspace 안에 여러 tab을 만들려면 `herdr tab create`를 사용한다.
3. plugin pane은 help가 `tab` placement를 명시적으로 지원하며, 현재
   `[[panes]] placement = "tab"` manifest를 실제로 열었을 때 새 tab/root
   pane을 만들었다.
4. workspace create → tab/pane/plugin 배치 → workspace close 전체 흐름은
   Herdr 0.8.2에서 실제 성공했다.
5. 서로 다른 여러 `[[panes]]` entrypoint가 각각 tab으로 열리는 세부 동작은
   이번 실행에서 직접 검증하지 않았으므로 추측으로만 남긴다. 직접 확인된
   다중 tab plugin 조합은 동일 entrypoint를 두 번 여는 경우다.
