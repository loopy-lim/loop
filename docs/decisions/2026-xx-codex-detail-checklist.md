## 1. 배경

`codex-detail-audit` 조사 결과, 현재 `apps/loop-mobile` 대화 GUI는 D4 렌더링 계약(멱등 렌더·상태 기계·steer 마커·자동 스크롤)은 충족하지만, Codex 앱 수준의 **정보 밀도와 미세 표현**이 결여돼 있다: 어시스턴트 텍스트가 마크다운 기호 그대로 평문 렌더되고, 툴 카드 접힘 상태에 인자 요약이 없으며, 메시지에 시간이 전혀 없고, 스크롤 이탈 시 복귀 수단이 없다. 접근성(터치 타깃·동적 타입)은 전면 미착용이다. 이 결정은 감사 문서의 갭 체크리스트를 **구현 위임 가능한 우선순위별 수용 기준**으로 고정한다 — 각 항목은 코드 검사, 단위 테스트, 또는 스크린샷 셋 중 하나로 기계 검증 가능해야 한다.

## 2. 결정 (한 단락)

감사 체크리스트(G1~G17)를 **P0(시각적·정보 디테일, C1~C10)과 P1(인터랙션 디테일, C11~C16) 16개 수용 기준으로 채택**하고, G17(타임라인 가상화)은 변경 없이 후속 트리거 조건만 문서화한다. 모든 변경은 `apps/loop-mobile` 표현 계층에 한정한다: 프로젝션·프레임·wire 타입 무변경(기존 프로젝션 필드 `final`/`argsJson`/`occurredAt`/`truncated`의 소비만 추가 — 신규 상태 0), 날짜 헤더는 타임라인 아이템 어휘에 넣지 않는 **렌더 파생 행**으로 처리(D4 §6 정신 준수), 마크다운 렌더러는 의존성 0의 자체 경량 렌더러(코드펜스·인라인코드·헤더·불릿·강조 5종 — 감사 권고 (b))로 도입하고 언어별 하이라이트는 후순위로 후퇴. steer 흐름(D4 §4)·raw 토글·기존 제출 표면은 일절 건드리지 않는다.

## 3. P0 — 시각적·정보 디테일 (시연 v8 핵심)

> 각 기준의 **검증 방법**은 `[코드 검사]` / `[단위 테스트]` / `[스크린샷]`으로 표기. 스크린샷 검증은 스크립트 세션(유료 호출 0)으로 재생한 대화 화면 시뮬레이터 캡처를 뜻한다.

### C1. 어시스턴트 마크다운 렌더 (G1)

어시스턴트 텍스트 블록이 경량 마크다운 렌더러를 통과한다. 지원 문법은 5종으로 폐쇄: 코드펜스(```), 인라인 코드(`` ` ``), 헤더(`##`), 불릿(`-`), 강조(`**`).

- [ ] **AC1-1** `[단위 테스트]` 렌더러 순수 함수에 5종 문법 각각 입력 → 대응 렌더 노드(kind: code/inlineCode/header/bullet/bold) 1건 이상 산출, 미지 문법 기호(`~~`)는 평문으로 보존.
- [ ] **AC1-2** `[스크린샷]` 어시스턴트 응답에서 `**`, `##`, `` ` `` 기호가 원문으로 보이지 않는다.
- [ ] **AC1-3** `[코드 검사]` `apps/loop-mobile/package.json` dependencies에 마크다운 라이브러리 신규 추가가 없다(의존성 0 유지).
- [ ] **AC1-4** `[코드 검사]` 렌더러는 프로젝션 텍스트를 **변경 없이 소비만** 한다 — 적목 후 텍스트의 재가공(재전송·상태 저장) 경로 0건(D4 §8 준수).

### C2. 코드블록 카드 + 복사 (G2)

코드펜스는 본문과 분리된 카드로 렌더된다: `colors.surfaceAlt` 배경, 모노폰트(`type.mono` 역할 경유 — 호출부 hex·폰트명 하드코딩 금지), 우상단 복사 컨트롤(글리프는 `ui/glyphs.ts` 어휘에 1개 추가 후 경유).

- [ ] **AC2-1** `[스크린샷]` 코드펜스가 본문과 시각적으로 분리된 카드로 보인다.
- [ ] **AC2-2** `[단위 테스트]` 복사 핸들러가 코드 원문(파싱 후, 마크다운 기호 제거)을 클립보드 API에 전달함을 스파로 검증. RN 코어 폴백으로 의존성 0이 가능하면 폴백 채택(AC3-1과 동일 원칙).
- [ ] **AC2-3** `[코드 검사]` 카드 색·폰트 참조가 `ui/tokens.ts` 역할명 경유다.

### C3. 툴 카드 접힘 한 줄 인자 요약 (G3)

접힌 툴 카드 헤더에 도구명 뒤 한 줄 요약이 붙는다. 요약 규칙은 표현 계층 단일 헬퍼(첫 문자열 인자/path류 키 우선, 없으면 `argsJson` 선두 N자) — overflow 단일 팩토리 원칙(ui-ux-guidance §9-13) 준수.

- [ ] **AC3-1** `[단위 테스트]` 헬퍼에 `{ path: "src/App.tsx" }` → `src/App.tsx`, `{ command: "bun test" }` → `bun test`, 빈 객체 → 빈 문자열(또는 argsJson 선두) — 3케이스 이상.
- [ ] **AC3-2** `[스크린샷]` 서로 다른 도구 3종(read/bash/edit 등)의 접힌 카드에 서로 다른 요약이 보인다.
- [ ] **AC3-3** `[코드 검사]` 요약은 `numberOfLines={1}` + `type.caption` + `colors.inkMute`이고 `argsJson`을 상태로 복제하지 않는다(렌더 시 파생).

### C4. 상태어 색 대비 (G4)

툴 카드 상태어(running/done/error·interrupted) 텍스트에 상태 글리프와 동일한 `status.color`를 적용한다. 색 제거 시에도 문자가 남는다(§5 색 비의존).

- [ ] **AC4-1** `[코드 검사]` `cardState` 스타일이 고정 `colors.inkMute`에서 상태 파생 색으로 변경됨. error/interrupted만 `colors.danger`, done은 ok, running은 warn 계열(§1 폐쇄 삼합).
- [ ] **AC4-2** `[스크린샷]` done 카드와 error 카드의 상태어가 색으로 구분되고, error 카드가 스캔에서 즉시 식별된다.

### C5. 결과 잘림의 정직한 표기 (G5)

- truncated 마커를 유계 근거를 밝히는 상수 문구로 교체하고, "종료 후 빈 결과" 카드와 "running(결과 없음)" 카드를 구분한다.
- [ ] **AC5-1** `[코드 검사]` truncated 문구가 상수(`…(truncated at N KB — wire budget)` 계열)로 소유되고 인라인 문자열 조합이 아니다(§7 문구 상수 원칙).
- [ ] **AC5-2** `[단위 테스트]` (a) `result_truncated: true` → truncated 문구 렌더, (b) `state=running && resultText===null` → 결과 영역 숨김, (c) 종료 + 빈 문자열 → `(no output)` 한 줄 — 3케이스.
- [ ] **AC5-3** `[스크린샷]` truncated 카드와 결과 없는 카드가 시각적으로 구분된다.
- [ ] **AC5-4** 전체 원문 보기는 제공하지 않는다(게이트웨이 `MAX_OUTPUT_BYTES` 유계 절단으로 앱에 원문이 부재 — 과잉 약속 금지). `[코드 검사]` 전체 보기 모달/확장 경로 0건.

### C6. 메시지 타임스탬프·상대 시간 (G6)

- 타임라인: 같은 역할 연속 블록의 **첫 행에만** `HH:MM` 캡션(`type.caption`, `colors.inkFaint`) — 밀도 예산(§3) 유지.
- 채팅 목록: 행에 상대 시간(`5m`, `2h`, `3d`, 초과 시 날짜) 표기.
- [ ] **AC6-1** `[단위 테스트]` 상대 시간 순수 함수: 5분 전→`5m`, 2시간 전→`2h`, 3일 전→`3d`, 10일 전→날짜 문자열 — 4케이스.
- [ ] **AC6-2** `[단위 테스트]` 연속 블록 타임스탬프 축약 함수: 같은 역할 연속 아이템의 2번째 이후 행은 캡션 없음 — 1케이스.
- [ ] **AC6-3** `[스크린샷]` 대화 화면에서 시간 캡션이 보이고, 채팅 목록 행에 상대 시간이 뜬다.
- [ ] **AC6-4** `[코드 검사]` 프로젝션 아이템의 `occurredAt`을 상태로 복제하지 않고 렌더 시 소비한다.

### C7. 스트리밍 타이핑 인디케이터 (G7)

- `final === false`인 어시스턴트 텍스트 뒤 커서 글리프(▍) + opacity 토글(2프레임 깜빡임, 타이머 기반 — RN `Animated` 불요).
- 텍스트 버퍼가 비어 있는 스트리밍 중 어시스턴트 자리에 기존 `glyph.busy`(···) 행 — 새 글리프 발명 금지(§6).
- [ ] **AC7-1** `[단위 테스트]` `final: false` 아이템 → 커서 렌더 플래그 true, `final: true` → false — 프로젝션 `final` 소비 1케이스.
- [ ] **AC7-2** `[코드 검사]` 커서 글리프·busy 행이 어휘 상수 경유다.
- [ ] **AC7-3** `[스크린샷]` 스트리밍 중 프레임(커서/··· 있음)과 종료 후 프레임(없음)이 정지 캡처로 구분된다.

### C8. 날짜 섹션 헤더 (G8)

렌더 전 파생 단계에서 인접 아이템의 `occurredAt` 현지 날짜가 바뀌는 지점에 중앙 정렬 날짜 캡션 행 삽입. 타임라인 아이템 어휘·프로젝션에 추가하지 않는다(D4 §6 — 날짜 헤더는 표현 파생 행).

- [ ] **AC8-1** `[단위 테스트]` 파생 함수: 어제 23:50 → 오늘 00:05 아이템 시퀀스 → 경계 1건, 같은 날 10아이템 → 0건 — 2케이스.
- [ ] **AC8-2** `[코드 검사]` 헤더 행이 프로젝션 상태나 렌더 map의 아이템 key 체계(AC-멱등, D4 §1)에 유입되지 않는다(파생 단계에서 key 접두사 분리).
- [ ] **AC8-3** `[스크린샷]` 날짜를 넘는 스크립트 세션에서 날짜 경계 헤더가 보인다.

### C9. 빈 상태 화면 (G9)

프레임 없는 세션 진입 시 타임라인 중앙에 안내 블록: 글리프(기존 어휘) + 2줄 문구(무엇이 비었나 / 다음 행동). 문구는 상수 소유(§7).

- [ ] **AC9-1** `[코드 검사]` 빈 상태 문구가 컴포넌트 인라인이 아닌 상수(또는 어휘 모듈)에서 온다.
- [ ] **AC9-2** `[단위 테스트]` `items.length === 0` → 안내 블록 렌더, `> 0` → 미렌더 — 1케이스.
- [ ] **AC9-3** `[스크린샷]` 빈 세션 화면에서 중앙 안내 블록이 보인다(채팅 목록의 기존 문구는 이미 양호 — 무변경).

### C10. 에러/재연결 상태 위계 (G10)

- `stale`(재연결 중) notice만 톤 상향(`colors.warn` + `glyph.statusRunning`), ended 등 흔한 상태는 최소 신호 유지(§1 강도 비례).
- `streamError`는 원문 덤프 대신 상태 요약 1줄.
- 제출 실패 시 캡션 옆 "다시 보내기" 텍스트 버튼 — 기존 `submit` 핸들러 재호출(드래프트 보존은 이미 구현됨).
- [ ] **AC10-1** `[코드 검사]` notice 렌더가 종류별 톤 분기(stale=warn, 나머지=현행)를 갖는다.
- [ ] **AC10-2** `[코드 검사]` `Stream: {streamError}` 원문 보간이 제거되고 상태 요약 상수로 교체됨.
- [ ] **AC10-3** `[단위 테스트]` 제출 실패 → draft 미클리어 + 재시도 핸들러가 동일 제출 경로를 재호출함을 스파 검증(steer 경로 포함 — 실행 중 재시도는 steer 엔드포인트로).
- [ ] **AC10-4** `[스크린샷]` stale와 ended notice가 서로 다르게 보인다.

## 4. P1 — 인터랙션 디테일

### C11. "맨 아래로" 버튼 (G11)

`following === false` && chat 모드일 때 타임라인 우하단 오버레이 pill 표시 → 탭 시 `scrollToEnd({animated:true})`, follow 재개는 기존 `onScroll` 엡실론(48pt) 재진입 경로 그대로.

- [ ] **AC11-1** `[코드 검사]` 버튼 가시 조건이 기존 `following` 상태 구독에만 의존(신규 상태 0).
- [ ] **AC11-2** `[단위 테스트]` follow 상태 머신 회귀 없음 — 기존 `paneProjection` 테스트 무변경 통과.
- [ ] **AC11-3** `[스크린샷]` 스크롤업 상태에서 우하단 버튼이 보인다.

### C12. 자동 스크롤 애니메이션 (G12)

`scrollToEnd({animated: true})`로 변경. 프레임 병합 간격 ≥250ms(D4 §2)라 애니메이션 중단돼도 수렴.

- [ ] **AC12-1** `[코드 검사]` `animated: false` 잔존 0건(해당 호출부).
- [ ] **AC12-2** `[스크린샷/수동]` 스트리밍 중 화면이 말미를 부드럽게 추적한다.

### C13. 채팅 목록 pull-to-refresh (G13)

`RunsList` 목록 `ScrollView`에 `RefreshControl`(`refreshing={loading}`, `onRefresh={reload}`) — `reload`는 기존 `useCallback` 재사용. Refresh 텍스트 버튼은 유지(§9-1 폐쇄 어휘 이중 수단 허용).

- [ ] **AC13-1** `[코드 검사]` `RefreshControl`이 기존 `loading`/`reload`에 연결, 신규 로딩 상태 0.
- [ ] **AC13-2** `[수동]` 목록 당김 → 갱신. 기존 목록 스냅샷 테스트 무변경 통과.

### C14. 터치 타깃 44pt (G14)

감사 확인 3건 미달 해소: 전송 버튼 32→44×44, raw 토글 hitSlop 확대(실효 ≥44px), 백 버튼 `minWidth/minHeight: 44` 명시.

- [ ] **AC14-1** `[코드 검사]` 3개 컨트롤의 스타일 수치로 실효 터치 영역 ≥44pt 입증(전송 44×44, raw 토글 hitSlop 합산, 백 버튼 min).
- [ ] **AC14-2** `[수동]` 컴포저 레이아웃이 44px 버튼을 수용(겹침·클리핑 없음).

### C15. 동적 타입 대응 (G15)

1단계: Screen 루트에 `maxFontSizeMultiplier` 상한(1.3)으로 클리핑 방지. 토큰 `lineHeight`의 배수 파생은 부담 대비 수익이 확인될 때 후속.

- [ ] **AC15-1** `[코드 검사]` 화면 루트 컴포넌트에 `maxFontSizeMultiplier` 설정 존재.
- [ ] **AC15-2** `[수동/시뮬레이터]` AX3 큰 텍스트에서 대화 화면 텍스트가 커지고 줄이 겹치지 않는다.

### C16. 카드 확장 전환 애니메이션 (G16)

툴 카드 펼침/접기에 RN 코어 `LayoutAnimation` preset 1줄. 햅틱은 **보류**(네이티브 의존성 리스크 — 감사 권고).

- [ ] **AC16-1** `[코드 검사]` `LayoutAnimation.configureNext`가 카드 토글 핸들러에 1회 호출, 외부 라이브러리 0.
- [ ] **AC16-2** `[수동]` 카드 펼침/접기가 전환 애니메이션된다.

### C17. 가상화 — 변경 없음, 트리거만 문서화 (G17)

- [ ] **AC17-1** `[코드 검사]` 타임라인 렌더 방식 무변경(`ScrollView` 유지), `FlatList` 도입 없음.
- [ ] **AC17-2** 문서 기록: 후속 트리거 = 장기 세션에서 아이템 상한(권고 500) 초과 + 스크롤 프레임 드랍 관측 시 `FlatList`+`inverted` 전환을 후속 결정으로 접수.

## 5. 구현 위임 순서 (감사 §5 채택)

1. 표현 기반: C1 → C2 → C7 (같은 렌더 컴포넌트 안에서 연쇄 — 가장 저렴)
2. 정보 밀도: C3 → C4 → C5 → C6 (전부 기존 프로젝션 필드 소비 추가 — 신규 상태 0)
3. 구조: C8 → C9 → C10
4. 인터랙션: C11 → C13 → C14 → C12 → C15 → C16

## 6. 경계 준수 요약

- **스키마/프로토콜 무변경:** wire 타입·codegen·게이트웨이·loop-core 변경 0건. 모든 기준이 `apps/loop-mobile` 표현 계층의 기존 프로젝션 필드 소비만 추가한다.
- **동작 불변:** D4 렌더링 계약(멱등 키, 델타 append→final 치환, 상태 기계, steer 순서 매칭), raw 토글, 컴포저 제출/steer 분기 — 전부 무변경이며 기존 테스트 회귀 없음이 수용 기준에 명시(AC7-1, AC11-2, AC13-2, AC10-3).
- **어휘 규율:** 신규 글리프는 복사 1개(C2)뿐이고 `ui/glyphs.ts` 경유. 색·문구·타입은 전부 토큰 역할명 경유. 빈 상태/잘림 문구는 상수 소유.
- **의존성:** 신규 npm 의존성 0을 원칙으로(마크다운 자체 렌더러, 클립보드 RN 코어 폴백 확인 시). 불가피하면 구현 전 명시 후 도입.

## 7. 후순위·보류 (이번 사이클 미실시)

- 언어별 코드 하이라이트 (감사 G2 후순위 권고 — 의존성 대비 수익 낮음)
- 햅틱 (G16 — 네이티브 의존성이 ios 빌드 파이프라인에 미치는 영향 검토 후)
- 동적 타입 전면 대응(토큰 lineHeight 배수 파생) — C15 1단계 클리핑 방지 후 체감 판단
- 타임라인 가상화 (C17 — 트리거 조건 문서화만)
- 전체 결과 원문 보기 (C5-4 — 원천 유계로 불가, 문서 명시)
- 파일·이미지 첨부 — 선행 결정 D5(M2) 소유, 본 결정이 다시 판단하지 않음

## 8. 시연 v8 촬영 포인트 (후속 태스크 인수)

P0 항목이 확대 캡처에서 드러나도록 스크립트 세션(유료 0)에 다음을 포함할 것: (1) 마크다운+코드블록 카드가 포함된 어시스턴트 응답(C1/C2), (2) 접힘 요약이 보이는 툴 카드 3종 상태(C3/C4/C5), (3) 스트리밍 커서(C7), (4) 날짜 헤더+시간 캡션(C6/C8), (5) "맨 아래로" 버튼(C11). 세션은 날짜 경계를 넘도록 재생(C8 캡처용).

## 9. 미해결 항목

- RN 코어의 클립보드 폴백 가능 여부(없으면 `@react-native-clipboard/clipboard` 의존성 1개 승인 필요) — C2 구현 착수 시 확정.
- 커서 깜빡임 타이머의 해제 시점(언마운트·final 도착) 누수 검증 — C7 구현 시 단위 테스트로 고정.
- `maxFontSizeMultiplier` 값(1.3 권고) — C15 시뮬레이터 확인에서 확정.
