# 결정: QR 원 페어링 — 페이로드 형식, 스캔 경로, 렌더 표면

## 1. 배경

운영자는 데스크톱 앱/CLI에서 연결 정보를 QR로 제시하고, 휴대폰으로 한 번 스캔하면 연결되어 이후 Tailscale 기반으로 연결이 유지되기를 요구한다. 토큰리스 모델(선행 결정 §D-A)이 확정되어 있으므로 QR에 담을 것은 비밀이 아니라 **연결 위치**뿐이다. 현재 모바일은 MagicDNS 호스트명·포트를 손으로 입력해야 하고(ConnectScreen), 데스크톱은 폼만 있다. QR은 이 수동 입력의 마찰을 제거하는 수단이며, 새 인증 메커니즘이 아니다.

## 2. 결정 (한 단락)

**QR 페이로드:** QR은 `loop://connect?host=<tailscale-host>&port=<port>` 형태의 URL 스킴 하나로 고정한다 — `host`는 게이트웨이의 Tailscale 주소(MagicDNS 호스트명 우선, iOS ATS가 숫자 IP를 ATS 예외에서 배제하는 현황과 일치), `port`는 게이트웨이 TCP 포트다. **토큰리스 모드에서는 QR에 비밀을 넣지 않는다** — tailnet 멤버십이 유일한 자격이므로 넣을 비밀 자체가 없고, bearer 폴백 모드에서는 토큰이 이미 Keychain 저장·생체인증 게이트 수명주기로 보호되는 자격증명이므로 **폴백 bearer를 QR에 실어 평문 노출하는 일은 금지**한다(폴백 모드 사용자는 기존 수동 입력 경로를 그대로 쓴다; QR은 토큰리스 전용 표면). **스캔 경로:** 권장 경로는 **시스템 카메라가 QR을 스캔 → `loop://` 스킴 딥링크가 앱을 연다** — iOS `CFBundleURLTypes`에 `loop` 스킴을 등록하고, 앱은 딥링크에서 host/port를 파싱해 기존 `createConnectionConfig` → 검증 프로브 → 성공 시 기존 저장 경로로 연결한다. 앱 내 카메라 스캐너는 폴백으로만 유지한다(카메라 권한·바코드 라이브러리 의존성을 기본 경로에서 회피). 딥링크가 불가능한 환경(시뮬레이터, 데스크톱 폰 없음)을 위해 **수동 host/port 입력은 폴백으로 남긴다.** **렌더 표면:** (1) 데스크톱 Tauri connect 화면이 QR을 렌더링하고, (2) CLI는 `loop pair` 명령으로 터미널에 ASCII QR + 평문 URL을 함께 출력한다 — QR 렌더링은 의존성 최소 원칙에 따라 작은 자체 구현(UTF-8 블록 문자 기반)으로 하되, 실현 불가 판단 시 단일 소형 의존성(`qrcode` 계열)을 명시적 근거와 함께 추가한다. **보안 노트:** QR이 Tailscale 밖으로 유출되어도 **tailnet 멤버가 아니면 `host:port`에 도달 자체가 불가능**하다 — CGNAT 주소·MagicDNS는 tailnet 밖에서 라우팅되지 않고, 게이트웨이는 활성 Tailscale 인터페이스에만 fail-closed 바인드한다. QR은 위치 공개일 뿐 자격 부여가 아니므로 만료·회전 메커니즘이 필요 없다.

### D-A. 페이로드 형식

- URL: `loop://connect?host=<host>&port=<port>`. 쿼리 파라미터는 두 개뿐이며, 미지 파라미터는 파서가 무시한다(후방 호환 확장점). `port`는 1..65535 정수.
- `host`는 MagicDNS 호스트명(예: `loopy-macbookpro.tail42f248.ts.net`)을 기본으로 한다 — ConnectScreen의 기본값과 iOS ATS Info.plist 예외가 이미 호스트명을 전제하므로 일관된다. CGNAT IP 리터럴도 파싱은 허용하되 iOS에서 ATS 제약을 문서로 경고한다.
- bearer 토큰, 시크릿, 경로, 사용자 식별 정보는 페이로드에 존재하지 않는다. 파서는 `token=`/`secret=` 계열 파라미터를 발견하면 **거부**한다(실수로 비밀을 넣은 QR을 조용히 수용하지 않음).
- 폴백(bearer) 모드와의 관계: QR 페어링은 토큰리스 모드 전용이다. 폴백 모드에서는 토큰이 QR에 들어갈 수 없으므로(§2), 폴백 사용자는 기존 수동 입력 + Keychain 저장 경로를 유지한다. 데스크톱/CLI는 현재 인증 모드를 알 수 없으므로(게이트웨이 바인드만 앎), QR에는 항상 연결 위치만 담고 모드 판단은 앱의 연결 프로브 결과에 맡긴다.

### D-B. 스캔 경로

1. **권장: 시스템 카메라 → 딥링크.** iOS `Info.plist`의 `CFBundleURLTypes`에 스킴 `loop`을 등록한다. 시스템 카메라가 QR을 스캔하면 배너의 `loop://connect?...` 링크 탭으로 앱이 열리고, 앱은 launch/open URL 인자에서 페이로드를 파싱해 Connect 화면에 host/port를 프리필한 뒤 자동 연결을 시도한다. 성공하면 기존 부모의 검증-후-저장 흐름(Keychain, 토큰리스 모드에서는 저장할 것 없음)이 그대로 실행된다. **카메라 권한·바코드 스캔 라이브러리를 기본 경로에 도입하지 않는다.**
2. **폴백 1: 앱 내 수동 입력(필수 유지).** Connect 화면의 host/port 텍스트 입력은 그대로 남는다 — 시뮬레이터 시연, 딥링크 미등록 빌드, 화면에서 직접 타이핑 선호 사용자를 커버하고, 기계 검증 가능한 폴백이기도 하다.
3. **폴백 2(선택, 후속): 앱 내 카메라 스캐너.** 필요성이 실증될 때까지 구현하지 않는다. 도입 시에도 `ui/` 계층 밖 신규 최상위 디렉터리 없이 `features/` 산출물로 귀속된다.

### D-C. 렌더 표면

- **데스크톱(Tauri) connect 화면:** 게이트웨이 설정(host/port)이 확정되면 QR을 화면에 렌더링한다. QR 인코딩은 순수 함수(페이로드 문자열 → 모듈 매트릭스)로 분리해 렌더러(DOM/SVG)와 무관하게 테스트한다.
- **CLI `loop pair`:** 게이트웨이 설정을 읽어 터미널에 (a) 평문 URL, (b) ASCII QR(UTF-8 블록 문자, 반쪽 블록으로 해상도 2배)을 출력한다. 호스트명은 Tailscale 설정/MagicDNS에서 유도하며 없으면 명시적 오류. `pair`는 연결을 수립하지 않는다 — 출력만 한다(읽기 전용, 상태 변경 없음).
- **의존성 원칙:** QR 인코더는 자체 최소 구현을 우선한다. QR 사양 구현 비용이 판단보다 커진다고 판단되는 경우에만 단일 소형 라이브러리를 채택하고, 채택 근거를 구현 PR 본문에 기록한다. 두 표면이 동일 인코더를 공유한다(위치는 계층 규칙 준수 범위에서 합의 — 예: 공유 `ui`/유틸 계층).

### 기각한 대안

| 대안 | 기각 이유 |
| --- | --- |
| QR에 bearer 토큰 포함(폴백 모드 지원) | QR 사진 한 장이 자격증명 유출이 됨; Keychain 수명주기의 보호를 우회; 토큰리스 모델과 충돌 |
| QR 대신 페이로드 URL만 표시 | 운영자 요구가 명시적으로 "QR 스캔"; URL만으로는 휴대폰 타이핑 마찰이 남음 |
| 앱 내 카메라 스캐너를 기본 경로로 | 카메라 권한 + 바코드 라이브러리 의존성이 항상 탑재됨; 시스템 카메라가 이미 존재하는 기능을 재구현 |
| 페어링 서버/단발성 페어링 코드 발급 | 발급 인프라가 v1 범위 밖; 토큰리스 설치 목표와 반대 방향 |
| 페이로드에 JSON 담기 | URL 스킴이 딥링크와 자연 결합하고 시스템 카메라가 링크로 인식; JSON은 추가 파서만 필요 |

## 3. 기계 검증 가능한 수용 기준

모두 유료 모델 호출·실기기 없이 검증한다:

1. **페이로드 왕복:** `loop pair`(및 데스크톱 QR 생성)의 출력에서 URL을 파싱하면 원래 게이트웨이 host/port와 동일한 `ConnectionConfig`가 복원된다 — `bun test` 유닛(인코더+파서 왕복, 포트 경계값 1/65535, 잘못된 포트·`token=` 파라미터 거부 포함).
2. **딥링크 연결 + 재시작 유지:** QR 페이로드를 딥링크로 주입(시뮬레이터 `openurl` 등)하면 앱이 연결에 성공하고, 앱 재시작 후에도 저장된 연결(토큰리스 모드에서는 host/port 설정, 폴백이면 기존 Keychain restore)로 자동 복원된다 — 기존 `restoreSession` 유닛 재사용 + 딥링크 파서 유닛.
3. **수동 폴백 존재:** Connect 화면의 수동 host/port 입력 경로가 기존 테스트와 동일하게 통과한다(제거되지 않음을 회귀로 보장).
4. **비밀 비포함:** 페이로드 생성기 출력에 bearer/secret 문자열이 절대 등장하지 않고, 파서가 `token=` 파라미터 포함 페이로드를 거부함을 유닛으로 검증.
5. **경계 준수:** QR 인코더/파서가 provider·Pi·모델 개념을 import하지 않음(아키텍처 테스트 규칙 준수); CLI 출력에 `[credential]=[redacted]` 규칙 적용.

## 4. 미해결 위험

- 시스템 카메라의 커스텀 스킴 QR 처리는 iOS 버전·설정에 따라 배너 표시 동작이 달라진다 — 실기기 없이는 시뮬레이터 딥링크 주입으로만 검증 가능하며, 실기기 스캔 UX는 별도 확인 항목으로 남는다.
- `loop pair`가 MagicDNS 호스트명을 자동 유도하는 경로가 환경마다 다르다(`tailscale status` 파싱 등) — 유도 실패 시 `--host` 플래그로 명시 입력을 받는 폴백이 필요할 수 있다.
- 자체 QR 인코더는 오류 수정 레벨·버전 선택 등 사양의 일부만 커버할 수 있다 — 페이로드가 짧아(호스트명+포트) 하위 버전·레벨 L로 충분하다고 판단되나, 생성된 QR을 실제 카메라로 읽히는 최종 확인은 사람 검증 항목이다.
- 데스크톱 connect 화면이 아직 게이트웨이 "실행자"가 아닌 "입력 폼"이라 QR에 넣을 host/port의 출처(데스크톱이 게이트웨이를 띄우는지, 이미 떠 있는 것에 붙는지)는 구현 태스크에서 확정해야 한다.
