# Decision: GPT-6 Primary Execution Lane Moves to pi (openai-codex)

- **Date:** 2026-09-23
- **Status:** decided
- **Kind:** decision
- **Read scope:** `config/models.toml`, `config/providers.example.toml`, `docs/model-routing.md`, `docs/decisions/2026-09-22-model-environment-generalization.md`, `docs/audits/2026-09-23-gpt6-models-verification.md`
- **Write scope:** `config/models.toml`, `config/providers.example.toml`, `docs/model-routing.md`, this document
- **Supersedes:** the codex-primary placement of gpt-6 recorded in `docs/audits/2026-09-23-gpt6-models-verification.md` (the codex entries remain, demoted to fallback)

## Context

gpt-6 luna/sol entered Loop on 2026-09-23 as codex-lane entries (`codex exec --json`, ChatGPT native login, smoke-verified on codex-cli 0.155.1). pi 0.87.1 now ships both ids in its built-in `openai-codex` provider catalog, making a pi-hosted gpt-6 lane possible without any custom-model metadata. The Lead chose option B: move the gpt-6 primary lane to pi.

## Evidence (Lead-provided smoke, 2026-09-23)

1. pi updated 0.87.0 → 0.87.1; `pi update --models` refreshed the catalogs.
2. `pi --list-models` lists `gpt-6-luna` and `gpt-6-sol` under `openai-codex` (272K context window, 128K max output tokens).
3. Headless smokes passed with ChatGPT native login:
   - `pi -p --provider openai-codex --model gpt-6-luna` → `OK-LUNA-PI`
   - `pi -m gpt-6-sol` → `OK-SOL-PI`

## Verdict

### 1. Lane move — pi is the gpt-6 primary lane

`config/models.toml` gains two entries mirroring the codex-lane gpt-6 capability/latency/cost figures:

- `id = "openai-codex/gpt-6-luna"`, `provider = "pi"`, `compute_class = "balanced"`
- `id = "openai-codex/gpt-6-sol"`, `provider = "pi"`, `compute_class = "frontier"`

No `[pi.models]` metadata tables are declared: both ids are in pi 0.87.1's built-in catalog, and the 2026-09-22 model-environment decision mandates metadata **only** for ids the built-in catalog lacks. The pi models.json sync (`packages/providers/src/pi/models-json.ts`) already skips metadata-less ids, so the built-in catalog entries remain untouched. The pi provider's native login is used; credentials stay in pi's own auth store and are never logged or persisted by Loop.

### 2. Codex entries stay as fallbacks

The codex-lane `gpt-6-luna` / `gpt-6-sol` entries (plus the gpt-5.6 luna/terra/sol line) remain unchanged:

- **Escalation needs a second lane.** Verification failure escalates one compute class; a single authenticated gpt-6 lane would leave frontier escalation with no independent retry path. The codex lane is already smoke-proven (OK-LUNA / OK-SOL on codex-cli 0.155.1), so keeping it costs zero new evidence.
- **Lane diversity isolates outages.** pi and codex are separate hosts, auth stores, and release trains; a pi-side regression (e.g., a catalog or adapter breakage) degrades routing instead of removing gpt-6 capacity.

### 3. Considered alternatives

- **Status quo (codex stays primary):** Rejected. It leaves gpt-6 on the one lane without the pi extension host (persona injection, models.json sync, Herdr tab interactivity per `docs/decisions/persona-ux.md` D2), while pi already carries the zai volume classes — consolidating the primary volume on pi gives gpt-6 the same worker surface and keeps codex as the dedicated fallback.
- **`pi-openai-service-tier` package:** Rejected for now. (a) It is an orthogonal concern — it models OpenAI service tier (priority processing), not lane selection, and Loop has no priority-tier requirement today. (b) It would insert a third-party dependency into the ChatGPT native login/auth path. (c) Its `supportedModels` list would duplicate model truth that `config/models.toml` plus pi's built-in catalog already own, violating the single-source-of-ids rule. Revisit only if a priority service tier becomes an actual requirement.

## Consequences

- Model count 14 → 16; `frontier` candidates 3 → 4 (`openai-codex/gpt-6-sol` ties on cost+latency and sorts last lexicographically).
- `packages/orchestrator/test/config.test.ts` frontier ordering assertion and `packages/cli/test/cli.test.ts` model-count assertion were updated to match (same invariants as the 2026-09-23 gpt-6 verification audit, extended by one candidate).
- No `loop-core`/`loop-bridge` changes; ids and provider endpoints live only in configuration.
